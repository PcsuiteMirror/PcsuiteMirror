PcsuiteMirror is a native SwiftUI **menu-bar agent** (`LSUIElement: YES` in
`project.yml`): launching it shows **no Dock icon and no window** — only an icon
in the top-right macOS menu bar. "Launched" is proven by the process being alive
and crash-free, not by a window appearing.

The `.app` links a Rust static lib (`../pcsuite-rs/target/release/libpcsuite_ffi.a`)
plus swift-bridge glue; the `.xcodeproj` is generated by [xcodegen] from
`project.yml` and is gitignored. All paths below are relative to the repo root.

## Step 1 — is the built app stale?

The Debug build lives at `build/DD/Build/Products/Debug/PcsuiteMirror.app`.
Rebuild if any Swift source **or** the Rust lib is newer than the app binary:

```bash
APP="build/DD/Build/Products/Debug/PcsuiteMirror.app/Contents/MacOS/PcsuiteMirror"
NEED=0
[ ! -x "$APP" ] && NEED=1
find Sources -name '*.swift' -newer "$APP" 2>/dev/null | grep -q . && NEED=1
[ ../pcsuite-rs/target/release/libpcsuite_ffi.a -nt "$APP" ] && NEED=1
echo "rebuild needed: $NEED"
```

If `NEED=0`, skip to Step 3 and just launch what's there.

## Step 2 — build (only if stale)

The Rust lib is usually already current (it's a separate, slow build). Rebuild it
**only if it's missing or you changed Rust code** in `../pcsuite-rs`:

```bash
[ -f ../pcsuite-rs/target/release/libpcsuite_ffi.a ] || \
  (cd ../pcsuite-rs && ./crates/pcsuite-ffi/build-macos.sh)
```

Then regenerate the project and build the Debug app:

```bash
xcodegen generate
xcodebuild -scheme PcsuiteMirror -configuration Debug \
  -derivedDataPath build/DD build CODE_SIGNING_ALLOWED=NO 2>&1 | tail -5
```

Expect `** BUILD SUCCEEDED **`. (A `CoreSimulator is out of date` warning from
xcodebuild is harmless — it's macOS-only, no simulator involved.)

## Step 3 — launch and verify it's alive

```bash
APP="build/DD/Build/Products/Debug/PcsuiteMirror.app"
open "$APP"
sleep 3
ps -o pid,etime,rss,command -p "$(pgrep -f "$APP/Contents/MacOS/PcsuiteMirror")" \
  || echo "NOT RUNNING — launch failed"
find ~/Library/Logs/DiagnosticReports -name 'PcsuiteMirror*' -mmin -2 2>/dev/null \
  && echo "^ crash report — it crashed on launch"
```

A stable PID with no fresh crash report = launched successfully.

## Driving it (what an agent can't do from the CLI)

Actually *using* the app — connecting a phone, opening the mirror window,
toggling settings — requires clicking its **menu-bar icon**, which can't be
driven from the shell. Report that this step is the user's to do on screen, and
tell them the app is in the menu bar (not the Dock). Ask the user before trying
any UI-automation workaround.

## Gotchas

- **No window on launch is correct**, not a failure. Don't look for one.
- **Two copies can run** — an old manually-launched Debug build plus a fresh one.
  `pgrep -lf PcsuiteMirror` to check; `pkill -f 'build/DD.*PcsuiteMirror'` the
  stale one before relaunching if needed.
- **`xcodebuild` errors about the Rust lib** (`library 'pcsuite_ffi' not found`)
  → the static lib is missing; run the Rust build in Step 2.
